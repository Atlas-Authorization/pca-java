# Changelog

## Unreleased (0.5.0)

- **Breaking (K5, security default):** `plan_root_authorized` is enforced by default. With no plan configured (`plan(null)`, no context plan, no registered plan) `Authorize.authorize` now FAILS the check with `plan_root_authorized: default-deny: no authorized plan is configured for this verifier (supply the plan and its authorization, or set insecureSkipPlanRootCheck)` instead of reporting `not-enforced`; this holds even when `require` omits the check. The `insecureSkipPlanRootCheck` opt-out belongs to the lower-level verifier only (not present in this SDK); `authorize` never accepts it.

- **New (K5, workflow and read-side gates):** `Workflow` (workflow/DAG admission: `admitStep`, `bindPromises`, `planRootAuthorized`, `validWorkflowBody`, `dagError`, `workflowDigest`, `valueDigest`, `receiptRef`) and `ReadSide` (read-grant redaction `redactRead`, `readChainLabels`, `checkSink`, `readGrantDigest`). Total and strict: anything malformed, unsigned, unknown or out of scope denies, integers only (`1.5` and `2500.0` are not integers), unknown members deny. Replays the shared `workflow-vectors.json` and `readside-vectors.json` in CI (`K5VectorsTest`); a missing file fails.
- **New (K5, workflow gate in authorize):** `Authorize.Input.workflow(new Authorize.WorkflowPin(principal, rsSigner, required))` and the per-call `workflowStep(new Authorize.WorkflowStep(commitment, receipts, step, units, goalDigest))`. When configured, `Workflow.admitStep` decides the call BEFORE the core checks and the replay counter (a refusal never consumes it): no step and `required` refuses with `workflow: this call carries no workflow step (fail closed)`; any non-allow refuses with status 403, check `workflow` = fail and reason `workflow: <code> (step <id>)` (an `escalate` result has `decision` = `escalate`, `allow` = false, no escalation request). The request carries the operation's verb/resource/params and the presented PCActn's `plan.root`. Absent option: unchanged. Replays `authorize-workflow-fixtures.json` (`AuthorizeWorkflowTest`); a missing file fails.
- **Changed/New (K5, workflow order and guards):** a `required` workflow with no step now refuses (403, check `workflow`) BEFORE the PCActn is read, so it needs none; an undecodable PCActn is never judged by the gate and is refused 401 with check `pcactn` and reason `undecodable PCActn: could not be decoded` (was check `wire`, `wire: PCActn could not be decoded`; an ABSENT PCActn still answers `wire: no PCActn presented`). `Authorize.Options.withWorkflow(WorkflowPin)` carries the pin; `PcaFilter` / `PcaInterceptor` take a per-request `withWorkflowStep(req -> WorkflowStep)` callback, else `PcaFilter` reads the JSON body member `workflow` {commitment, receipts, step, units, goal_digest} (the interceptor never reads the body); a malformed member or a throwing callback is a step that is refused; `PcaCore.authorize` has a matching overload. Refusals match `authorize`: 403 `workflow: <code> (step <id>)`. Tests: `GuardWorkflowTest`.
- **New (K5, tokenisation vault and aggregate reads, C-315..C-319):** `ReadVault`: `memoryVault`, `redactReadWithVault`, `detokenize`, signed-grant verification, `aggregateRead` (k-anonymity floor, clamp, query cap, epsilon budget, repeat queries answered free from the state) and the integer-exact discrete Laplace sampler (`seededDraws`, `discreteLaplace`; `secure` noise draws a fresh CSPRNG seed, the production setting). Replays `vault-aggregate-vectors.json` (`ReadVaultTest`); a missing file fails.
- Added (K9): `Sigstore` verifies a Sigstore bundle offline against a pinned `trusted_root.json` (`parseTrustedRoot`, `verifySigstoreBundleCore`, `verifyRfc3161`): Rekor v1 `dsse`/`intoto` and Rekor v2 `hashedrekord` entries, RFC 3161 and SET time sources, RFC 9162 inclusion to a signed checkpoint, the Fulcio path at every verified time, embedded SCTs, the DSSE signature and the Fulcio identity. `verifySigstoreBundle` returns the SLSA v1 facts `ProvenanceGate.provenanceGate` checks. JDK crypto only. Replays `sigstore-vectors.json` (`SigstoreVectorsTest`).
- **New (K7, what you see is what you sign):** the canonical approval render (`render`, `H(R)`, the approval challenge, the six-word match code), PSD2 Article 5 linking and the batch commitment, and `render_digest` on escalation requests and answers (the binding refuses an answer for another render, with none, or carrying a render the verifier did not recompute). Replays the shared `approval_*` vectors and the `approval-profiles` vectors byte for byte.
- Added: caveat language v2 (`CaveatLang`): third-party `needs_discharge` caveats satisfied by signed discharges from verifier-pinned issuers (`verifyDischarge`, `dischargeDigest`, `dischargeActionDigest`), `sealed`, the holder-signed `narrow` block (`verifyNarrow`), `max_uses` spent through the replay store (`reserveMaxUses`, `maxUsesSlotKey`), bounded Kleene three-valued `derive` caveats, `spiffe_bound` and `spiffeIdError`; `evaluateK1` / `evaluateCaveatsK1`. `Authorize.Input.k1(...)` and `usesStore(...)` opt in; K1 caveat types are taken out of the stock evaluator's lists and, without that input, stay unsatisfied. Replays the shared `caveat-lang-vectors.json` (all six primitives) in CI.

Vectors `k1_unconfigured`, `consume_once_ttl`, `k1_headers` run in `CaveatLangVectorsTest`.

- 0.5 (additive): the signed PCActn member `fresh_at` (a consistency token). It is validated first (closed key set, canonical counters, signer and signature encodings) and covered by the leaf signature. `Pca.verifyPcactn(..., K3.FreshAtPolicy)` adds a `fresh_at` check after the intent checks: reported only when the PCActn carries the member, a side-carried token is read, or the policy requires one. - **Breaking** (0.5): "unconfirmed means maximally dangerous". A def without a valid human confirmation now has EVERY trait of the registry (`Actions.topTraits`): `Actions.effective(def, reg[, pins])` gains `confirmed`, `traitsOf(def, reg, pins)` replaces `traitsOf(def)`, and review state `authored` no longer counts. ## 0.4.1

- Security (policy layer): caveats on the root grant outside the envelope are now evaluated like delegated caveats; new policy_caveats/evaluate_caveats helpers (incl. max_spend). The core verifier still does not evaluate caveats. Java: `Caveats.policyCaveats(grant, chain)` (the grant's caveats minus its first `envelope` caveat, then the caveats the hops appended) and `Caveats.evaluateCaveats(caveats, ctx)` -> `Caveats.Result{ok, failed}` (total; `expires`, `not_before`, `rate`, `max_blast_radius`, `reversibility_max`, `delegation_depth`, `budget_alloc`, and the new `max_spend {usd}`; anything else fails closed). `Pca.verifyPcactn`, `PcaFilter` and `PcaInterceptor` are unchanged and still treat caveats as opaque: a resource server enforcing a grant's caveats calls `Caveats.evaluateCaveats(Caveats.policyCaveats(grant, chain), ctx)` with its own action params. New `primitives.caveat_eval` vectors run in `ConformanceTest`.
- Wire: threshold-share signatures are validated per suite (`Pq.validateShareSignatureWire`): `alg` absent = ed25519 (64-byte `sig`, no `pq_sig`), `ml-dsa-65` (3309-byte `sig`, no `pq_sig`), `hybrid-ed25519-ml-dsa-65` (64-byte `sig` + 3309-byte `pq_sig`); a non-string (incl. null) or unknown `alg` is a wire refusal. Only an absent or empty header falls back to the body. New `primitives.pca_header` vectors run in `ConformanceTest` and `PcaMiddlewareTest`.

## Unreleased (BREAKING)

- Depth / R6-05 (parity + robustness): every protocol digest (capHash and the hop body digest, Merkle leaves, params / conditions digests, the threshold signer-set hash) now uses the STRICT canonical form, exactly as the reference `hash.ts` `canonicalBytes`. Before, these were hashed under the lenient form, so a hop or leaf signed over out-of-profile bytes (nesting deeper than 32, a lone surrogate, a non-canonical number) verified where the reference refuses it, and a deeply nested (or cyclic) caveat, Merkle leaf or grant overflowed the stack: the `StackOverflowError` escaped `verifyChain` / `verifyInclusion` / `verifyPcactn` (they catch only `RuntimeException`).   `ml-dsa-65` or `hybrid-ed25519-ml-dsa-65` ROOT hop (hop 0) previously verified under the `pq_pk` carried by the root
  artifact itself, so an attacker-minted root naming a victim Ed25519 issuer, signed with the attacker's own ML-DSA key,
